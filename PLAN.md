# План расширения local-ai

От текущего стека (чат + код) к личному ассистенту в Telegram и «цифровому
двойнику», говорящему в твоём стиле. Фазы независимы — можно брать по одной.

## Карта компонентов

```
                       ┌─────────────────────────────┐
   Open WebUI (3000) ──┤                             │
   Telegram-бот     ──┤        Ollama (11434)        ├── GPU (RTX 3070 Ti)
   IDE-плагин       ──┤   модели: qwen / my-twin     │
   CLI / скрипты    ──┤                             │
                       └─────────────────────────────┘
```

Ollama — единое ядро. Всё остальное — это «рты» к нему. Добавление интерфейса
не трогает движок и данные.

---

## Фаза 0 — Базис ✅ (готово)
Ollama + Open WebUI, GPU, модели `qwen2.5-coder:7b` и `qwen2.5:7b`, веб-чат.

---

## Фаза 1 — Доступы (низкая трудоёмкость, высокая отдача)

Способы общаться с моделью помимо веб-чата:

| Способ | Как |
|---|---|
| **CLI (разово)** | `.\ai.ps1 "вопрос"` — скрипт уже в репо |
| **CLI (интерактивно)** | `docker exec -it ollama ollama run qwen2.5-coder:7b` |
| **REST API** | `POST http://localhost:11434/api/generate` — из любого скрипта/кода |
| **IDE** | JetBrains → плагин **ProxyAI**; VS Code → **Continue/Cline**; указать `http://localhost:11434` |

Глобальный алиас (чтобы `ai "..."` работал из любой папки) — добавить функцию
в `$PROFILE` PowerShell. Подниму по команде.

## Фаза 2 — Telegram-бот (ассистент)

Отдельный контейнер мостит Telegram ↔ Ollama. Это же — будущая «оболочка»
двойника.

**Готовые проекты** (форкаем, не пишем с нуля):
- `m0wer/aibot` — текст + голосовые, docker-compose, system-prompt.
- `ruecat/ollama-telegram` — популярный, простой, whitelist пользователей.
- `mlloliveira/TelegramBot` — мультимодельный, веб-поиск, vision.

**Добавить сервис в `docker-compose.yml`:**
```yaml
  telegram-bot:
    image: ghcr.io/ruecat/ollama-telegram:latest
    container_name: tg-bot
    restart: unless-stopped
    environment:
      - TOKEN=${TELEGRAM_TOKEN}          # токен из .env (gitignored!)
      - OLLAMA_BASE_URL=http://ollama:11434
      - INITMODEL=qwen2.5:7b             # позже заменить на my-twin
      - USER_IDS=ТВОЙ_TELEGRAM_ID        # whitelist: только ты (защита GPU)
    depends_on: [ollama]
    networks: [ai_net]
```

**Шаги:**
1. Создать бота у `@BotFather` → получить токен.
2. Токен — в `.env` (НЕ в код/git; политика секретов проекта).
3. Узнать свой Telegram ID (`@userinfobot`) → в `USER_IDS` (иначе любой посторонний
   будет жечь твою видеокарту).
4. `docker compose up -d telegram-bot`.

⚠️ Бот слушает Telegram-серверы напрямую (это нормально), но доступ к модели —
только из whitelist. Наружу порт не открывается.

## Фаза 3 — Знания (RAG + веб)

- **Веб-поиск** — уже включён в Open WebUI (DuckDuckGo).
- **RAG по личным заметкам** — подключить Obsidian-хранилище (`E:\development\my-life`)
  как источник: модель отвечает с опорой на твои заметки. Монтировать **только для
  чтения**.
- Личное/чувствительное — держать в отдельной коллекции, не смешивать с рабочим.

## Фаза 4 — Цифровой двойник (цель)

Дообучение модели на твоих переписках, чтобы отвечала в твоём стиле.

**Конвейер (отдельный trainer-контейнер с GPU):**
1. **Данные:** экспорт чатов Telegram (JSON) → нарезать в пары «контекст → твой ответ».
2. **Обучение:** QLoRA через **Unsloth** (на 8 ГБ влезает 7–8B, ~6–7 ГБ VRAM).
3. **Экспорт:** в **GGUF** (квант `Q4_K_M`); Unsloth сам генерит `Modelfile`.
4. **Импорт в Ollama:** `ollama create my-twin -f Modelfile`.
5. **Подключить:** в боте (Фаза 2) `INITMODEL=my-twin` → он отвечает «как ты».

**Трезво об ожиданиях:** это имитация **стиля** (словечки, тон, типовые реакции),
а не сознание. В коротких диалогах убедительно; решения за тебя не принимает.
Качество прямо зависит от объёма и качества твоих сообщений в выборке.

## Фаза 5 — Железо (когда возьмёшь 16/24/32 ГБ)

Больше VRAM → крупнее базовая модель → лучше и код, и двойник. Подробности и
перенос данных — в [UPGRADE.md](UPGRADE.md).

> Ограничение 8 ГБ сейчас: **код-модель и двойник одновременно в VRAM не
> помещаются** (каждая ~5 ГБ) — Ollama выгружает одну, грузит другую (задержка
> на переключение). 16 ГБ+ позволит держать обе сразу.

---

## Рекомендованный порядок

`Фаза 1 (доступы)` → `Фаза 2 (Telegram-бот на готовой модели)` →
`Фаза 3 (знания)` → `Фаза 4 (двойник)` → `Фаза 5 (железо, по возможности)`.

Сначала запусти бота на обычной модели — убедишься, что мост работает, и только
потом вкладывайся в дообучение двойника.
